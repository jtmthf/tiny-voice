## Dependency notes

- **003 → 004**: 004 rewrites drain semantics and the revenue projection; 003
  pins the invariants (delete-only-after-success, enqueue atomicity,
  retention) that must survive. Running 004 first leaves the rework without a
  safety net; running 003 after 004 requires re-scoping its assertions.
- **008 → 009**: 009 adds a `getInvoiceDetail` query; after 008 that's one
  wiring site (`wire-queries.ts`) instead of three files in lockstep.
- **004 and 007** are independent but both touch transactional semantics —
  land as separate PRs, not combined.
- **001, 002, 005, 006, 010** are fully independent and safe to run in
  parallel with anything (002 and 006 both edit `package.json` — trivial merge,
  different keys).

## Findings considered and rejected

Recorded so future audits don't re-litigate them:

- **`SqliteInvoiceRepo.save` deletes/re-inserts all line items per save** —
  intentional whole-aggregate persistence (AGENTS.md rule 2); plan 006 adds a
  doc note saying so. Not a defect.
- **No pagination on invoice/client lists** — real gap, wrong scale; demo
  datasets never hit it. Revisit only if the repo grows a data-volume story.
- **No `.editorconfig`** — Prettier + CI already own formatting; marginal value.
- **Seed/migrate script tests** — dev tooling, low blast radius; the migration
  runner is already checksum-guarded and idempotent.
- **`createInvoice`/`deleteInvoice` live outside `applyInvoiceCommand`** —
  deliberate, documented in ADR-0001. Do not re-suggest pulling them in.
- **Missing authentication/authorization** (incl. IDOR-by-id on read fns) —
  intentional omission per AGENTS.md; auth would obscure the patterns the repo
  demonstrates.
- **`InProcessEventBus.publish` throwing AggregateError on partial subscriber
  failure** — kept by design ("all subscribers run, caller can detect");
  plan 004 makes the *outbox* tolerant instead of changing bus semantics.
- **Replacing the bracket-notation parser with a library (qs)** — one 36-line
  file doesn't justify a dependency with its own CVE history; plan 001 hardens
  it in place.
